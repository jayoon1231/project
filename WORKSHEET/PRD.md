# PRD: 약속 준비 시간 계산 앱

## 1. 개요

**제품명**: 약속 준비 가이드 앱 (On-Time Assistant)

**한 줄 설명**: 약속까지의 이동시간과 개인 준비시간을 종합적으로 계산해서, 약속에 늦지 않기 위해 언제부터 준비를 시작해야 하는지 알려주고 알람을 울려주는 모바일 앱

**타겟 플랫폼**: iOS / Android (모바일 네이티브 또는 크로스플랫폼)

---

## 2. 문제 정의 (Problem Statement)

### 현황
- 약속 시간에 맞추려고 노력하는 사람들이 실제로는 자주 늦음
- 사용자가 주관적으로 준비시간을 예상하면 샤워, 양치, 옷 입기, 머리 말리기 등 개별 항목의 시간을 과소평가하는 경향이 있음
- 준비시간만 고려할 뿐, 교통상황(실시간 정보)을 반영하지 못해 더욱 늦게 출발함

### 구체적 불편함
1. **시간 관리 실패**: "30분이면 준비할 수 있겠지?" → 실제로 필요한 시간은 45분 → 결국 늦음
2. **변수 미반영**: 날씨, 교통 혼잡도 등 예측 불가능한 요소를 대비하지 못함
3. **수동 계산의 번거로움**: 매번 준비시간 + 이동시간을 직접 계산해야 함

### 기대 효과
- 사용자가 지각(遅刻)하는 횟수 감소
- 약속 시간에 여유 있게 도착 가능
- 준비 과정을 체계화할 수 있음

---

## 3. 목표 (Goals)

### MVP 단계 목표
1. **정확한 준비시간 계산**: 개별 준비 항목(샤워, 양치, 옷 입기, 머리 말리기 등)의 소요시간을 설정 후, 합산한 총 준비시간 제시
2. **실시간 이동시간 제공**: 약속 장소까지의 실시간 교통정보를 기반으로 이동시간 계산
3. **준비 시작 시각 역산**: (약속 시간 - 준비시간 - 이동시간)을 계산해서 "준비 시작 시각" 알려주기
4. **시간 알림**: 계산된 준비 시작 시각에 사용자에게 알람/푸시 알림 발송
5. **간편한 입력 인터페이스**: 약속 장소와 시간을 빠르게 입력할 수 있는 UI 제공

---

## 4. 비목표 (Non-Goals)

다음 기능들은 **MVP 단계에서는 구현하지 않음**:

- **캘린더 자동 연동**: 스마트폰 캘린더(Google Calendar, Apple Calendar 등)와의 자동 동기화
- **소셜 기능**: 친구와의 약속 공유, 그룹 일정 관리
- **다중 프로필**: 여러 사용자 계정 관리
- **인공지능(AI) 학습**: 사용자의 지각 패턴 분석 및 자동 조정 (향후 확대 시 고려)
- **다국어 지원**: 한국어 지원에 집중

---

## 5. 타겟 사용자 (Target Users)

### Primary User Persona
- **이름**: 청소년 / 직장인 (특히 20대 초반)
- **특징**: 약속에 자주 늦는 경향이 있거나, 시간 관리가 약함
- **니즈**: 약속 시간에 맞게 도착하고 싶지만, 직접 계산하기 번거로움
- **사용 빈도**: 주 2~3회 이상 약속이 있을 때 사용

### 사용 시나리오
- "내일 친구와 3시에 만나기로 했는데, 집에서 어디까지 얼마나 걸리지?"
- "오전 10시 면접인데 늦으면 안 되니까 정확히 몇 시에 나가야 할까?"

---

## 6. 사용자 시나리오 / 주요 사용 흐름

### 시나리오 1: 새로운 약속 설정
1. 사용자가 앱을 열고 **"새 약속 추가"** 버튼을 탭
2. **약속 정보 입력 화면**:
   - 약속 장소 (주소 검색 또는 지도에서 선택)
   - 약속 시간 (시간/분 선택)
   - 약속 이름 (선택사항: "친구 만나기", "면접" 등)
3. 시스템이 자동으로 **현재 위치**에서 약속 장소까지의 **실시간 이동시간** 계산
4. 사용자가 **준비 항목별 소요시간** 설정 (또는 기본값 사용):
   - 샤워: 20분
   - 양치: 5분
   - 옷 입기: 10분
   - 머리 말리기: 15분
   - 기타 (선택사항): 10분
5. 시스템이 자동 계산:
   - 총 준비시간: 60분
   - 이동시간: 20분 (교통정보 기반)
   - **준비 시작 시각** = 약속 시간(3시) - 준비시간(60분) - 이동시간(20분) = **1시 40분**
6. "준비 시작 시각: 오후 1:40" 화면에 표시
7. 사용자가 **"알람 설정"** 버튼을 탭하면, 1시 40분에 알람 활성화

### 시나리오 2: 알람 받기
- 설정된 시각(예: 오후 1:40)에 앱이 알람/푸시 알림 발송
- 알림 내용: "지금부터 준비를 시작해야 오후 3시 약속에 제시간에 도착합니다"
- 사용자가 알림을 탭하면 앱이 열리고, 남은 시간(1시간 20분) 카운트다운 표시 (선택사항)

## 7. 기능 요구사항 (Functional Requirements)

### 7.1 약속 정보 입력
- **FR-1**: 사용자가 약속 장소를 입력할 수 있어야 함
  - 주소 직접 입력 또는 지도에서 선택 가능
  - 최근 약속 장소 자동 제안 (선택사항)
  
- **FR-2**: 사용자가 약속 시간을 입력할 수 있어야 함
  - 시간/분 단위 선택
  - 시간 단위로 정렬되어 있을 것

### 7.2 준비 시간 계산
- **FR-3**: 기본 준비 항목(샤워, 양치, 옷 입기, 머리 말리기 등) 제공
  - 각 항목당 기본값 시간 제시
  - 사용자가 개별 항목의 시간을 커스텀할 수 있어야 함
  
- **FR-4**: 사용자 정의 준비 항목 추가 가능
  - 예: "화장", "신발 신기", "가방 싸기" 등 추가 가능
  
- **FR-5**: 총 준비시간을 자동 계산하고 표시
  - 모든 선택된 항목의 시간을 합산

### 7.3 이동 시간 계산
- **FR-6**: 사용자의 현재 위치에서 약속 장소까지의 이동시간을 **실시간 교통정보** 기반으로 계산
  - 공공 교통 API(예: Naver Map API, Kakao Map API, Google Maps API 등) 활용
  - 대중교통, 자동차, 도보 등 이동 수단별 옵션 제시 (선택사항)
  
- **FR-7**: 이동시간에 안전 여유시간(버퍼) 자동 추가 (선택사항)
  - 기본값: +5~10분 추가 (변수 대비)

### 7.4 준비 시작 시각 계산
- **FR-8**: 다음 공식으로 준비 시작 시각 자동 계산:
  ```
  준비 시작 시각 = 약속 시간 - 준비시간 - 이동시간 (- 여유시간)
  ```
  - 계산 결과를 명확하게 표시 (예: "오후 1시 40분")

### 7.5 알람/알림
- **FR-9**: 계산된 준비 시작 시각에 알람 또는 푸시 알림 발송
  - 앱이 포그라운드(실행 중)일 때: 인앱 알림 또는 음성 알람
  - 앱이 백그라운드일 때: 푸시 알림 (O/S 수준)
  
- **FR-10**: 알림을 받은 후 사용자가 "완료", "5분 연장" 등의 액션을 선택할 수 있어야 함 (선택사항)

### 7.6 약속 목록 관리
- **FR-11**: 설정된 약속 목록을 보여줌 (오늘, 내일, 이번주 등 필터)
- **FR-12**: 개별 약속을 수정/삭제할 수 있어야 함

## 8. 비기능 요구사항 (Non-Functional Requirements)

### 8.1 성능
- **NFR-1**: 약속 정보 입력 후 준비 시작 시각 계산 완료 시간 < 2초
- **NFR-2**: 교통정보 API 응답 시간 고려 (네트워크 지연 발생 가능)

### 8.2 정확도
- **NFR-3**: 교통정보 제공 API의 이동시간 오차 범위 ±5분 이내로 관리
  - 실시간 데이터 특성상 100% 정확도 보장 불가능하므로, 사용자 리뷰 및 피드백으로 지속 개선

### 8.3 신뢰성
- **NFR-4**: 알람/알림이 설정된 시각에 99% 이상 발송되어야 함
  - 백그라운드 알람 기능의 안정성 필수
  - 각 OS(iOS/Android)의 백그라운드 제약사항 준수

### 8.4 보안
- **NFR-5**: 사용자의 위치 정보는 앱 내에서만 사용하며, 외부 서버에 저장하지 않음 (선택사항)
  - 또는 필요시 익명화 처리

### 8.5 지원 플랫폼
- **NFR-6**: iOS 13.0 이상 지원
- **NFR-7**: Android 8.0(API 26) 이상 지원

## 9. 성공 지표 (Success Metrics)

### 정량적 지표
1. **약속 지각 감소율**: 앱 사용 전/후 비교 시 사용자의 지각 횟수 30% 이상 감소
2. **알람 사용률**: 활성 사용자 대비 알람 설정 비율 > 80%
3. **재방문율**: 월 3회 이상 앱 사용 사용자 비율 > 60%
4. **계산 정확도**: 사용자가 앱 제시 시간에 출발했을 때 제시간 도착 비율 > 85%

### 정성적 지표
1. 사용자 리뷰 평점 > 4.0/5.0
2. 사용자 피드백에서 "시간 관리가 쉬워졌다" 언급 비율 높음

## 10. 기술적 고려사항 (Technical Considerations)

### 10.1 필수 API & 라이브러리
- **지도/교통정보 API**: 
  - Naver Map API, Kakao Map API, 또는 Google Maps API
  - 실시간 경로 탐색 및 소요시간 제공
  
- **위치 정보**: 
  - iOS: Core Location
  - Android: Google Play Services (Location API)
  
- **로컬 알람/알림**: 
  - iOS: UserNotifications Framework
  - Android: WorkManager, AlarmManager, 또는 Firebase Cloud Messaging (FCM)

### 10.2 데이터 저장
- **로컬 저장소**: SQLite (또는 Realm)
  - 약속 목록, 설정값 등 저장
  
- **클라우드 동기화** (향후 고려): 
  - 여러 기기 간 약속 동기화 필요시 Firebase Realtime Database 또는 REST API 고려

### 10.3 개발 플랫폼 옵션
- **네이티브**: Swift(iOS) + Kotlin(Android) — 성능 최적화, OS 기능 최대 활용
- **크로스플랫폼**: Flutter, React Native — 개발 속도, 코드 공유
  - 초보자 입장에서는 Flutter 권장 (한국 커뮤니티 활발, Dart 학습 곡선 낮음)

### 10.4 권한 (Permissions)
- **iOS**: Location, Notification, Calendar (선택사항)
- **Android**: ACCESS_FINE_LOCATION, POST_NOTIFICATIONS, READ_CALENDAR (선택사항)

## 11. 오픈 이슈 / 향후 고려사항 (Open Questions)

### 11.1 기능 범위
- Q1: 준비 항목의 개인화 저장 여부? (사용자 맞춤 항목 리스트)
  - 현재: 기본값 제시 + 개별 편집
  - 향후: 사용자 프로필별 자동 학습
  
- Q2: 다중 약속 동시 관리 여부?
  - 예: "3시 약속", "5시 약속" 동시 설정 가능?
  - MVP에서는 단일 약속 기준으로 진행, 향후 확대

- Q3: 반복되는 약속(정기 모임, 학원 시간 등) 지원?
  - MVP: 미지원
  - 향후: 반복 일정 추가 고려

### 11.2 사용 경험
- Q4: 앱이 닫혀 있을 때도 알람 작동?
  - iOS/Android 백그라운드 정책 확인 후 결정
  - 백그라운드 프로세스 유지의 배터리 영향 평가 필요

- Q5: 준비 과정 중 카운트다운(타이머) 표시?
  - MVP: 기본 시각 계산 + 알람만 제공
  - 향후: 인앱 타이머, 진행률 표시 등 추가 가능

### 11.3 데이터 & 프라이버시
- Q6: 사용자 위치 정보를 로그/분석하는가?
  - MVP: 로컬 저장소만 사용 (외부 전송 안 함)
  - 향후: 익명화된 통계 수집 시 동의 필요

- Q7: 클라우드 백업 필요?
  - MVP: 불필요 (로컬 저장소만)
  - 향후: 여러 기기 동기화 필요시 추가

## 13. 부록: 용어 정의

- **준비시간**: 사용자가 외출을 위해 필요한 준비 과정의 총 시간 (샤워, 옷 입기 등)
- **이동시간**: 출발지에서 약속 장소까지 이동하는 데 걸리는 시간 (교통정보 기반)
- **여유시간(버퍼)**: 예상 시간에 추가로 확보하는 안전 시간
- **푸시 알림**: OS 수준의 알림 (앱이 실행 중이지 않을 때도 수신 가능)
- **인앱 알림**: 앱 내에서 표시하는 알림
